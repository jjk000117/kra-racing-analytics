# API4 Raw와 연승 Snapshot Feature 대조

## 기술 요약

2026-08-11 API4 상태 확인을 위해 2022년 서울 1페이지·1행 요청을 정확히 한 번 실행했다. HTTP는 200이었지만 API는 다시 `resultCode=99`, `가용한 세션이 존재하지 않습니다. (100/100)`을 반환했다. 추가 요청과 2022·2023 전체 수집은 실행하지 않았다.

현재 2024~2026 API4 Raw의 89개 필드는 모두 Staging에 원문 문자열로 보존된다. 그러나 첫 Snapshot 29개와 모델 입력 28개에는 속도·구간·마체중·날씨·주로 Feature가 없다. 구간기록은 Canonical에 별도 컬럼이 없고, `wgHr`는 `485(+7)` 같은 복합 문자열을 숫자로 직접 변환해 Canonical `horse_weight`가 49,386행 모두 NULL이다. `rcTime`은 Canonical `race_time INTEGER`로 변환되면서 49,386행 중 43,521행에서 원문의 소수값과 달라져 속도 계산 원천으로 적합하지 않다.

따라서 후속 속도·페이스 Feature는 기존 계약대로 Staging의 개별 과거 경주 원문을 `race_date < feature_as_of`로 집계해야 한다. 현재 Snapshot과 baseline_v1은 변경하지 않는다.

## 1. API4 단일 요청 재확인

| 항목 | 결과 |
|---|---|
| 요청 | 2022년, 서울(`meet=1`), 1페이지, 1행 |
| 실제 API 요청 횟수 | 1회 |
| HTTP 상태 | 200 |
| API 상태 | `API_ERROR` |
| resultCode | `99` |
| 메시지 | `가용한 세션이 존재하지 않습니다. (100/100)` |
| 전체 수집 | 시작하지 않음 |
| 추가 재시도 | 수행하지 않음 |

이 결과는 현재도 전체 수집을 재개할 수 없는 상태라는 뜻이다. API 키는 출력·저장하지 않았고 최소 요청은 Raw나 DuckDB에 기록하지 않는 상태 확인용 요청이었다.

## 4. 현재 모델에 없는 API4 원천 필드

현재 29개 Snapshot Feature는 API4의 경주 기본정보와 과거 말·기수·조교사 이력을 최소 범위로 집계한다. 아래 74개 Raw 필드는 Snapshot Feature로 직접 표현되지 않는다.

### 속도·구간기록 43개

- 서울 누적기록: `seS1fAccTime`, `seG3fAccTime`, `seG1fAccTime`, `se_1cAccTime`, `se_2cAccTime`, `se_3cAccTime`, `se_4cAccTime`
- 서울·제주 통과순위: `sjS1fOrd`, `sjG3fOrd`, `sjG1fOrd`, `sj_1cOrd`, `sj_2cOrd`, `sj_3cOrd`, `sj_4cOrd`
- 부산경남 누적기록·순위·구간: `buS1fTime`, `buS1fAccTime`, `buS1fOrd`, `buG1fAccTime`, `buG1fOrd`, `buG2fAccTime`, `buG2fOrd`, `buG3fAccTime`, `buG3fOrd`, `buG4fAccTime`, `buG4fOrd`, `buG6fAccTime`, `buG6fOrd`, `buG8fAccTime`, `buG8fOrd`, `bu_10_8fTime`, `bu_8_6fTime`, `bu_6_4fTime`, `bu_4_2fTime`, `bu_3fGTime`, `bu_2fGTime`, `bu_1fGTime`
- 제주 기록: `jeS1fTime`, `jeG3fTime`, `jeG1fTime`, `je_1cTime`, `je_2cTime`, `je_3cTime`, `je_4cTime`

`rcTime`은 그 자체가 Snapshot Feature는 아니지만 DNS·완주 상태 판정과 과거 이력 모집단 구성에 간접 사용되므로 위 74개 미사용 목록에서는 분리했다.

### 경주 조건·상금·환경 18개

`ageCond`, `budam`, `buga1`, `buga2`, `buga3`, `chaksun1`, `chaksun2`, `chaksun3`, `chaksun4`, `chaksun5`, `prizeCond`, `rcDay`, `rcName`, `sexCond`, `name`, `weather`, `track`, `ilsu`

### 표시·관계자·마체중 10개

`hrName`, `hrNameEn`, `jkName`, `jkNameEn`, `trName`, `trNameEn`, `owNo`, `owName`, `owNameEn`, `wgHr`

### 사후 결과·시장정보 3개

`diffUnit`, `winOdds`, `plcOdds`

식별자·날짜·착순·레이팅 등 나머지 원천은 현재 기본 Feature, 과거 이력 집계, 모집단·상태 판정 또는 lineage에 이미 사용된다. 위 목록이 “필드가 불필요하다”는 뜻은 아니며 첫 기준모델의 입력에서 제외돼 있다는 뜻이다.

## 5. 속도·구간 Feature 후보

### 우선 후속 후보

1. 과거 `rcTime`을 초 단위 실수로 파싱한 최근 3회·5회 요약
2. 서울 `seS1fAccTime`과 부산경남 `buS1fTime`을 경마장별 표준 원천으로 매핑한 최근 S1F 요약
3. 서울 `seG3fAccTime`/`seG1fAccTime`과 부산경남의 결승 구간 필드를 의미별로 매핑한 최근 G3F/G1F 요약
4. `wgHr`를 마체중과 증감으로 분리한 과거 최근값·변동성
5. 과거 날씨·주로상태·함수율과 거리 조건을 결합한 조건별 이력

이 후보들도 그대로 모델에 넣는 것이 아니라 경마장·거리 정의를 통일하고, 정상 출전과 유효 기록만 남기며, 현재 경주일 미만의 과거 경주만 집계해야 한다.

### 후순위 고도화

- 서울·부산경남 코너/구간 통과순위와 위치 변화
- 거리별로만 존재하는 1C/2C, G6F/G8F 기록
- 주로·거리·경마장을 보정한 속도지수
- 페이스 유형과 막판 가속/감속 구조

거리별 미통과 `0`을 결측으로 단순 치환하면 거리 정보와 구조적 결측을 혼동할 수 있으므로 거리별 적용 가능 구간표가 먼저 필요하다.

## 6. 2022·2023 수집 상태별 다음 경로

### 현재 결과: 실패

- 이번 단계는 여기서 중단한다.
- 실패 Raw batch는 그대로 보존한다.
- 다음 승인 시 단일 상태 요청을 다시 실행한다.
- 같은 `99 / 100/100`이면 다시 중단하고 전체 수집을 시작하지 않는다.

### 향후 단일 요청 성공 시

1. 새 batch로 2022년 서울·부산경남 전체 Raw를 수집한다.
2. 2022 Raw/Manifest audit과 연도·월·경마장 건수를 확인한다.
3. 새 batch로 2023년 전체 Raw를 수집하고 같은 audit을 수행한다.
4. Staging 적재는 별도 승인 전까지 수행하지 않는다.

## 7. 검증 범위와 제한

- 공식 API4 명세 DOCX의 94행 응답 필드 표와 실제 Staging 89개 원천 필드를 대조했다.
- 실제 2024~2026 Staging 49,386행과 Canonical 4,600경주·49,386출전행을 읽기 전용으로 집계했다.
- Snapshot 29개와 모델 입력 28개는 코드 상수와 물리 테이블 컬럼으로 대조했다.
- DOCX 렌더링은 로컬 LibreOffice 실행 파일을 찾지 못해 수행하지 못했으며, 본문 49개 문단과 7개 표 전체를 구조적으로 읽었다.
- Snapshot 재생성, Feature 추가, 모델 학습, baseline_v1 변경, Final Test 재평가는 수행하지 않았다.

## 다음 추천 작업

API 상태가 회복되기 전에는 수집 재시도보다 후속 Feature 실험 명세를 먼저 확정할 필요가 없다. 상태가 정상화되면 2022·2023 Raw 수집·audit을 우선 완료하고, 이후 별도 버전에서 `rcTime`·S1F·G3F/G1F·마체중 파서와 가용성 검사를 설계하는 것이 가장 안전하다.
