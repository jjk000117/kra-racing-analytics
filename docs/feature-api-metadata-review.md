# 6C 사전 검토: 연승 Feature 후보와 KRA API 메타데이터 대조

검토일: 2026-08-08  
상태: 범위 결정 전 검토 완료, Feature 계산·Snapshot·추가 수집 미실행

## 결론

현재 `API4_3` 결과 원장만으로도 첫 개발용 기준모델에 필요한 Point-in-Time 과거 이력은 만들 수
있다. 말·기수·조교사의 과거 성적, 최근 폼, 휴식일수, 거리·경마장·등급 경험이 핵심 후보다.

다만 현재 경주의 기본 출전정보도 결과 API에서 사후 수집한 값이다. 의미상 경기 전에 정해지는
항목이라도 실제 예측시점 가용성을 더 강하게 입증하려면 공식 경기 전 원천이 필요하다. 그 역할은
`API26_2` 출전표 상세정보가 가장 직접적이며, `API72_2` 경기계획은 경주 조건과 계획시각을
보완한다.

단, 지금 과거 날짜를 조회해 받은 `API26_2` 응답은 그 경기 전에 실제로 보였던 값의 증거가
아니다. 수집시각은 지금으로 기록되므로 역사적 예측시점 계약은 자동으로 보강되지 않는다.

- **첫 기준 Snapshot에 사용 가능**: 현재 `API4_3`에서 과거 경기만으로 산출하는 이력과,
  경기 전 의미가 명확한 기본 조건 중 승인된 항목
- **추가 수집 우선 검토**: `API26_2`의 현재 경기 출전표·레이팅·부담중량·출발시각·경주조건
- **조건부 보완**: `API72_2` 경기계획, 말 조교 이력, 정적 혈통·개체정보
- **현재 경주에는 보류**: 마체중, 날씨, 주로상태, 배당·인기도, 현재 누적 성적·상금

`API26_2`를 수집하더라도 누적 성적·상금 11개 필드는 참고 저장소에서 Point-in-Time 오류가 이미
확인됐으므로 사용하지 않는다. 누적 이력은 계속 `API4_3`에서 직접 계산한다.

## 2. 현재 보유 데이터

현재 보유 원천은 `API4_3` 경주결과 89개 필드와 `API179_1` 매출·확정배당이다. Canonical의
모집단·DNS·타깃 무결성은 승인된 입력으로 승계한다.

| 범주 | 현재 가능한 정보 | 예측시점 판정 |
|---|---|---|
| 경주 맥락 | 일자, 경마장, 경주번호/명, 거리, 등급, 연령·성별·상금·부담 조건, 등록두수 | 값은 있음. 현재 경기 사용은 사전 의미 확인 필요 |
| 출전마 기본정보 | 말 ID, 마번, 성별, 연령, 레이팅 | 값은 있음. ID·마번 외 속성은 사전 원천과 대조 권장 |
| 관계자 | 기수·조교사·마주 ID와 명칭 | 공식 ID는 이력 집계키로 사용 가능 |
| 부담 조건 | 부담중량 | 값은 있음. 현재 경기 값은 출전표 원천으로 보강 권장 |
| 말 신체 | `wgHr` 마체중 | Canonical valid-start 48,524행에서 전부 결측, 사용 불가 |
| 과거 경기 | 착순, 경주기록, 구간기록/순위, 배당, 날씨, 주로상태 | `과거 경주일 < 현재 경주일`일 때만 이력 후보 |
| 현재 경기 결과 | 착순, 기록, 결과상태, 단승·연승배당 | 타깃·사후평가 전용, Feature 금지 |
| 매출·확정배당 | `API179_1` | 사후 시장정보, Feature 금지 |

현재 데이터에서 바로 만들 수 있는 실제 후보는 다음과 같다. 계산식과 창 크기는 아직 확정하지
않는다.

- 말: 과거 출전수, 첫 관측 출전 여부, 휴식일수, 과거 연승 적중률, 1/2/3착률, 유효 완주율,
  최근 성적·기록, 거리·경마장·등급별 경험
- 기수·조교사: 과거 출전수, 연승/입상 성적, 최근 성적
- 조합: 말–기수·말–조교사·기수–조교사의 과거 출전수와 성적
- 조건: 경마장, 거리, 등급, 성별, 연령, 마번, 부담중량, 등록두수
- 안전 플래그: 각 엔터티의 `prior_count`, `history_available`, `history_complete`,
  `source_max_event_date`

역사적 보존범위, 공개시점이 불명확하다. 첫 Snapshot 범위에는 넣지 않는다.

## 4. 범주별 보유 데이터와 추가 가능 데이터 비교

| 범주 | 현재 보유로 가능한 후보 | 추가 API 후보 | 현재 제안 |
|---|---|---|---|
| 경주 조건 | 경마장·거리·등급·조건·등록두수 | API26, API72 | 기본 후보. 현재 행 출처는 API26로 보강 권장 |
| 출전마 기본 | 말 ID·마번·성별·연령·레이팅 | API26의 산지·레이팅·최종 출전표 | 기본 후보. 산지·레이팅은 API26 수집 시 확대 |
| 과거 능력/폼 | API4_3 이전 결과로 대부분 계산 | API26 누적필드는 사용 금지 | **현 데이터 우선**, 추가 수집 불필요 |
| 관계자/조합 | API4_3 공식 ID로 과거 집계 | 기수/조교사/마주 현재 프로필 | **현 데이터 우선**, 현재 누적 API 불필요 |
| 부담 조건 | 현재/과거 부담중량 | API26 현재 부담중량, 변경 API | 개발은 가능. 운영 전 최종 변경 추적 필요 |
| 신체/준비도 | 과거 마체중도 현재 적재상 결측 | 조교 이력; 공식 사전 마체중 원천은 미확정 | 조교는 후속. 마체중은 보류 |
| 혈통/개체 | 없음 | API42 또는 개체식별 API | 기준모델 이후 ablation 후보 |
| 환경 | 결과 API의 날씨·주로 | 공식 사전시각이 입증된 KRA 원천 미확정 | 현재 경기 사용 보류; 과거 조건 이력만 가능 |
| 시장 | 결과 API 배당, 확정배당·매출 | 인기도 API | 첫 비시장 모델에서 제외 |
| 최종 모집단 | 사후 valid-start 프록시 | API26 + 변경/취소 공지 | 연구용은 현 정책 유지; 운영 전 보강 필요 |

## 5. 예측시점 가용성 판정 규칙

| 등급 | 의미 | 이번 검토의 예 |
|---|---|---|
| 승인 가능 | 이벤트일과 수집시각이 예측시점보다 이르고 값의 의미가 고정됨 | API4_3의 과거 경기 이력 |
| 조건부 | 의미상 경기 전 정보지만 역사적 공개·정정 시점을 아직 재현하지 못함 | API26·API72의 현재 경기 값 |
| 후속 검증 | 날짜는 있으나 공개 지연·정정·과거 범위를 확인해야 함 | 조교 이력, 기수 변경 |
| 금지/보류 | 사후 값이거나 현재 누적 스냅샷, 또는 공개시점 미확정 | 현재 경기 결과·배당·매출, 현재 누적 성적, 마체중·날씨·주로 |

공식 Feature로 승인하려면 `available_at <= feature_as_of`와
`source_max_event_date < race_date`를 모두 만족해야 한다. API 응답의 현재 값만 조회해 과거 경기의
당시 값을 복원했다고 간주하지 않는다.

## 6. 다음 범위 결정을 위한 선택지

### 선택지 A — 현재 데이터만으로 첫 Snapshot

- 말·기수·조교사·조합의 Point-in-Time 과거 이력과 승인된 기본 조건만 사용
- 장점: 추가 수집 없이 기준 파이프라인·시간순 검증·Calibration을 빠르게 완성
- 한계: 현재 경기 출전표의 역사적 as-of 근거와 산지·사전 레이팅·출발시각이 약함

### 선택지 B — API26_2를 과거 범위에 추가

- 공식 경기 전 출전 행과 현재 조건을 별도 Raw로 확보
- 장점: 결과 API와 출전표 필드의 구조·범위·일치 여부를 대조할 수 있음
- 한계: 지금 받은 과거 응답은 당시 경기 전 스냅샷의 증거가 아니며, 누적 11개 필드는 여전히 금지

### 선택지 C — API26_2 + API72_2 추가

- 출전표와 경기계획을 함께 저장해 계획 조건·출발시각·변경을 대조
- 장점: 현재 경주 계약과 lineage가 가장 명확함
- 한계: 중복 필드와 변경 이력을 관리해야 하며 첫 개발모델에는 범위가 커질 수 있음

## 권장안

**첫 역사적 기준 Snapshot의 기본안은 A**다. 지금 과거 `API26_2`를 수집해도 과거 경기의
진짜 사전 스냅샷이 되지는 않으므로, 현재 데이터에서 누수 없이 만들 수 있는 이력으로 먼저
파이프라인·시간순 검증·Calibration을 완성하는 편이 단순하다. 결과는 실제 발매마감 시점 모집단
기반 운영 성능으로 표현하지 않는다.

실제 운영이나 Paper Trading으로 갈 계획이 구체화되면 `API26_2`를 **미래 경기부터 경기 전에
주기적으로 수집**해 진짜 as-of 증거를 축적하는 것을 권장한다. 과거 범위 수집은 역사적 값의
불변성이 공식 문서나 샘플 검증으로 입증될 때만 첫 Snapshot 범위에 포함한다. `API72_2`, 조교,
혈통은 기준모델 이후 추가가치를 검증할 후보로 남긴다.

## 미확정 사항

- API26_2 및 변경정보의 실제 공개시각과 최종 발매마감 사이의 관계
- 현재 경기 마체중·날씨·주로상태의 공식 원천과 공개시각
- 조교 이력의 역사적 제공범위와 정정 정책

이 항목은 API 호출 없이 메타데이터만으로 확정할 수 없다. Feature 범위가 승인된 뒤 최소 샘플
수집과 Manifest 시각을 이용해 별도 검증한다.

소수 표본 8개를 실제 호출해 API4와 대조한 결과, API26의 통산·최근1년 출전 및 1·2·3위 횟수는
