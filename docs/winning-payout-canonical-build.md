# 공식 적중배당 Canonical 구축

구축일: 2026-08-02  
변환 버전: `canonical_v2`  
파서 버전: `winning_payout_v1`

## 목적과 Grain

`canonical.winning_payout`은 API179의 한 `confirmed_odds_raw` 행에 포함된 공식 적중 조합을
각각 별도 행으로 저장한다.

Grain은 `경주 × 승식 × 공식 적중 조합`이다. 동착 시 단승·복승·쌍승·삼복승·삼쌍승에도
복수 적중 조합이 생길 수 있으므로 기존 `canonical.sales_dividend`의 `경주 × 승식` Grain과
분리했다.

## 주요 컬럼

- `winning_payout_id`: 조합 행 식별자
- `sales_id`, `race_id`, `pool_code`: 원본 매출·경주·승식 연결
- `combination_no`: 한 원문 안의 조합 등장 순서
- `selection_count`: 승식이 요구하는 마번 수
- `horse_no_1`~`horse_no_3`: 정수형 마번
- `combination_key`: 비교와 중복 검사에 사용하는 조합 키
- `order_matters`: 쌍승식·삼쌍승식 여부
- `confirmed_odds`: 숫자형 공식 확정배당
- `confirmed_odds_raw`: 변경하지 않은 API 원문
- `parse_status`, `parser_version`: 파싱 결과와 버전
- `source_staging_row_id`, `source_batch_id`: 원천 lineage

쌍승식과 삼쌍승식은 원문 순서를 유지한다. 복승식·복연승식·삼복승식은 마번을 오름차순으로
정규화한 조합 키를 저장한다.

## 감사 규칙

- 모든 매출·배당 원문은 한 개 이상의 적중 조합을 가져야 한다.
- 모든 조합은 원본 `sales_id`, 경주, 승식, 배당 원문과 일치해야 한다.
- 배당은 양수이고 마번은 1~16이어야 한다.
- 선택 수와 마번 컬럼의 개수는 승식 구조와 일치해야 한다.
- 조합 마번은 해당 경주의 유효 출전마와 일치해야 한다.
- 단승·복승·쌍승·복연승·삼복승·삼쌍승의 조합 수는 공식 1~3위와 동착 구조에 맞아야 한다.
- 연승식은 1·2위 또는 1·2·3위 조합을 허용한다.

## 연승식의 발매 기준 주의사항

연승식은 출주마가 7두 이하일 때 1·2위만 적중한다. 그러나 현재 경주결과 API의 등록두수와
최종 유효 출전두수만으로 발매 시점의 적용 기준을 완전히 복원할 수 없다. 8두 등록 후 한두가
제외된 사례에서 2개 적중마와 3개 적중마가 모두 관찰됐다.

따라서 Canonical은 공식 배당 원문을 기준으로 2개 또는 3개 조합을 보존한다. 제외 시점을
추정하여 공식 적중 조합을 임의로 바꾸지 않는다.

## Point-in-Time

확정배당은 경주 후 확정되는 정보다. 모델 Feature에 포함하지 않으며 시장 분석과 백테스트
정산에서만 사용한다.
