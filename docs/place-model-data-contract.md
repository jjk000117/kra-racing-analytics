# 6A 연승 모델링 데이터 계약

결정일: 2026-08-02  
상태: 승인된 설계 계약, 미구현

## 목적과 범위

첫 완성 모델은 경주별 출전마의 공식 연승 적중확률을 예측한다. 6A는 학습 데이터가 지켜야 할
의미와 시간 경계를 확정한다. 실제 Feature 목록, 추가 API 목록, 학습 테이블, 모델과
Calibration 구현은 이 문서의 범위가 아니다.

## 예측 질문과 행 Grain

예측 질문은 다음과 같다.

> 연승 발매가 정상적으로 이루어진 경주에서, 베팅 결정시점에 선택 가능한 각 말이 공식 연승
> 적중마가 될 확률은 얼마인가?

- 한 행의 Grain: `경주 × 베팅 가능 출전마`
- 업무키: `race_id + horse_id`
- 한 경주의 모든 행은 동일한 데이터 분할에 속한다.
- 모델 출력: 각 행의 `place_hit_probability` (`0` 이상 `1` 이하)
- 말별 확률의 합을 임의로 1로 제한하지 않는다. 한 경주에 공식 연승 적중마가 여러 마리이기
  때문이다.

## 예측시점과 Point-in-Time

운영 가정은 **연승 발매 마감 직전, 경주 시작 전** 예측이다. 현재 원천에 정확한 발매 마감
타임스탬프가 없으므로 초기 일 단위 이력 Feature의 `feature_as_of`는 경주일로 둔다.

이력 기반 정보는 다음 조건을 반드시 만족해야 한다.

```text
source_event_date < race_date
```

- 같은 날짜의 다른 경주 결과도 과거 이력으로 사용하지 않는다.
- 현재 경주의 결과, 착순, 경주기록, 결과 상태, 확정배당과 매출은 Feature로 사용할 수 없다.
- 경주·출전표 정보라도 발매 마감 전에 알려졌다는 근거가 있어야 Feature 후보가 될 수 있다.
- 가용시점이 불명확한 값은 승인 전까지 Feature에 포함하지 않는다.
- 타깃과 학습 모집단을 사후에 판정하기 위한 필드는 Feature 영역과 물리적·논리적으로 분리한다.

## 학습 모집단

### 경주 포함 조건

다음을 모두 만족하는 경주만 지도학습 후보가 된다.

1. `canonical.race.race_status = 'COMPLETED'`
2. `canonical.winning_payout`에 `pool_code = 'PLC'`인 공식 적중 원문이 존재
3. 연승 적중 조합 파싱이 성공하고 적중마가 해당 경주의 말과 일치
4. 경주 안에서 베팅 가능 모집단을 일관되게 구성할 수 있음

`RACE_CANCELLED`, `RESULT_NOT_FINALIZED`, 연승 미발매·결과 누락·파싱 실패 경주는 제외한다.
제외는 음성 타깃으로 대체하지 않으며 제외 사유를 남긴다.

### 말 포함 조건

- 실제 베팅 대상이었던 말만 예측 모집단에 포함하는 것이 원칙이다.
- `FINISHED`, `DISQUALIFIED`, `RACE_STOPPED`처럼 실제 출전이 확인된 말은 결과와 무관하게
  모집단에 남긴다.
- 발매 마감 전에 취소·제외되어 환불 대상이 된 말은 모집단에서 제외한다.
- `DNS`, `SCRATCHED`, `EXCLUDED`, `NON_STANDARD_UNRESOLVED`,
  `CANCELLED_STOPPED_OR_DISQUALIFIED`는 현재 사후 상태만으로 발매 마감 당시의 베팅 가능 여부를
  추정하지 않는다.

현재 Canonical의 `is_valid_start`는 결과 해석용 필드이며 예측시점의 발매 대상 여부와 동일하다고
간주하지 않는다. 6B에서 현 데이터로 모집단을 복원할 수 있는지 확인하고, 불가능하면 해당 상태가
있는 경주를 초기 모델에서 제외하거나 별도의 사전 출전정보가 필요한 것으로 분류한다.

## 타깃 계약

타깃명은 `place_hit`이며 값은 `0` 또는 `1`이다.

```text
place_hit = 1  if horse gate number is present in the official PLC winning payout
place_hit = 0  otherwise, within the approved betting-eligible population
```

- 타깃의 유일한 근거는 `canonical.winning_payout(pool_code='PLC')`의 공식 적중마 목록이다.
- 등록두수나 최종 유효 출전두수로 2착·3착 범위를 다시 계산하지 않는다.
- 동착 때문에 공식 적중마가 추가된 경우 모든 공식 적중마를 양성으로 보존한다.
- 공식 적중마와 경주 출전마를 결합할 때 `race_id + gate_no`를 사용하고, 최종 행 식별은
  `race_id + horse_id`를 사용한다.
- 공식 적중마가 모집단에 없거나 중복 결합되면 해당 경주를 조용히 보정하지 않고 계약 위반으로
  처리한다.
- `confirmed_odds`는 타깃 생성 근거가 아니며 Feature에도 포함하지 않는다.

## Feature 분류 원칙

6A에서는 실제 Feature 이름을 정하지 않고 다음 분류 원칙만 확정한다.

1. **사전 고정 정보**: 발매 마감 전에 값이 확정되고 가용 근거가 있는 정보
2. **과거 이력 파생 정보**: `source_event_date < race_date`를 만족하도록 생성한 정보
3. **가용시점 미확인 정보**: 의미는 있어도 언제 알 수 있었는지 입증되지 않은 정보
4. **사후 정보**: 현재 경주 결과·경주기록·상태·매출·확정배당처럼 결과 후 생성되는 정보

1과 2만 Feature 후보가 될 수 있다. 3은 보류하고 4는 금지한다. 식별자, 타깃, 분할키와 lineage
필드는 Feature가 아니라 데이터 관리 컬럼으로 별도 취급한다.

## 추가 API 판단 원칙

6A에서는 API 목록이나 수집 여부를 결정하지 않는다. 6B에서 필요한 Feature 개념과 현재 데이터의
가용성을 대조한 후 다음 조건을 모두 만족할 때만 추가 수집 후보로 올린다.

- 예측시점 전에 실제로 이용 가능한 정보다.
- 기존 Canonical과 과거 이력으로 동일 의미를 만들 수 없다.
- 누수 없이 시점별 과거값을 재구성할 수 있다.
- 예상 활용가치가 수집·정합성·유지 비용보다 충분히 크다.
- 업무키, 갱신주기, 결측과 수정 이력을 추적할 수 있다.

## 날짜순 분할 계약

- Train, Validation, Final Test는 경주일 기준의 연속되고 겹치지 않는 과거→미래 구간으로 둔다.
- 동일 경주의 모든 말은 같은 구간에 배치한다.
- 무작위 행 분할과 미래 경주가 과거 경주보다 앞 구간에 들어가는 분할은 금지한다.
- 정확한 날짜 경계는 6B에서 월별 경주 수와 양성 수를 확인한 뒤 정하되 규칙은 먼저 고정한다.
- Train은 모델 적합, Validation은 Feature·모델·Calibration 선택에 사용한다.
- Final Test는 모든 선택이 끝난 뒤 한 번의 최종 평가에만 사용한다.
- Calibration은 Train 또는 시간순 Out-of-Fold 예측으로 적합하고 Validation에서 선택한다.
  Final Test 타깃으로 Calibration을 재적합하지 않는다.

## 평가 계약

첫 모델의 목적은 확률 품질 검증이다.

### 주 평가

- Log Loss
- Brier Score
- Calibration curve와 calibration intercept/slope 또는 동등한 요약

행 단위 지표와 함께 경주별 지표를 먼저 계산한 뒤 경주 간 평균한 결과를 병기한다. 이로써
출전두수가 큰 경주가 평가를 과도하게 지배하는지를 확인한다.

### 보조 평가

- 경주 내 확률 순위가 공식 적중마를 상위에 배치하는 정도
- 예측확률 구간별 표본 수와 실제 적중률
- 경마장·등급·출전두수·기간별 확률 품질의 안정성

Accuracy, 고정 임계값 Precision/Recall과 ROI는 첫 확률모델의 주 선택 기준으로 사용하지 않는다.
ROI와 확정배당은 별도의 사후 백테스트 계약에서 다룬다.

## 품질 실패 조건

다음 중 하나라도 발생하면 학습 데이터 생성을 실패로 처리한다.

- 업무키 `race_id + horse_id` 중복
- 타깃이 `0/1` 이외이거나 결측
- 공식 PLC 적중마가 모집단과 일치하지 않음
- 현재 경주 또는 같은 날짜 결과가 이력 Feature에 포함됨
- 사후 정보나 가용시점 미승인 Feature가 포함됨
- 한 경주의 행이 여러 데이터 분할에 걸침
- 날짜 구간이 겹치거나 시간 순서가 뒤바뀜
- 제외된 행·경주의 사유와 개수를 추적할 수 없음

## 복승 후속 모델과의 경계

복승 조합 직접 분류는 경주·말 식별자, Point-in-Time Feature 원천, 시간순 분할, 누수 검사,
확률평가와 Calibration 절차를 재사용할 수 있다. 그러나 행 Grain과 타깃은
`경주 × 비순서 2두 조합`으로 별도 생성한다. 연승 확률을 곱하거나 다른 임의 공식으로 변환해
복승 확률로 사용하지 않는다.

## 6B로 넘기는 확인사항

1. 현재 데이터가 발매 마감 당시의 베팅 가능 출전마 모집단을 복원할 수 있는가?
2. 각 Feature 개념은 현재 데이터로 생성 가능하고 가용시점이 입증되는가?
3. 월별 경주·행·양성 수를 기준으로 적절한 분할 날짜는 무엇인가?
4. 모집단 제외가 지역·등급·출전두수 분포를 편향시키는가?
5. 가용하지 않은 Feature 중 추가 API 검토 가치가 있는 것은 무엇인가?
