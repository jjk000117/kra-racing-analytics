## 2026-08-01 — API4_3과 API179_1 Raw 범위 및 결합 프로파일링

### 실험 내용

- 동일한 과거 기간과 서울·부산경남 범위에서 경주결과와 매출 API를 수집했다.
- 업무키 중복, 필수값, 날짜 범위, 경주 결합률과 승식 구성을 검사했다.

### 결과

- 경주결과: 49,386행, 4,600경주
- 매출·확정배당: 32,074행, 4,582경주
- 매출이 존재하는 모든 경주는 7개 승식 행을 보유했다.
- 경주결과에는 있지만 매출이 없는 경주는 18건이었다.

### 해석

- 경주결과와 매출은 별도 Grain의 데이터셋으로 유지해야 한다.
- 매출 누락은 곧바로 0원으로 해석할 수 없으며 상태와 완전성을 확인해야 한다.

## 2026-08-02 — 비표준 `ord`와 경주 상태 검토

### 실험 내용

- `ord` 0, 91, 92, 93, 94, 95, 99의 분포와 `rcTime` 조합을 확인했다.
- 참고 저장소 정책, 한국마사회 조회 결과와 실제 경주 사례를 대조했다.

### 결과

- 93·94·95와 `rcTime=0` 조합은 DNS 규칙으로 사용할 수 있었다.
- `ord=99` 11행은 한 경주에 집중되어 있었고 다량 낙마로 인한 경주 취소로 확인됐다.
- 2025-12-26 부산경남 6경주는 전체 취소로 분류했다.
- 2026-07-06의 9경주는 결과 미확정으로 분류했다.

### 해석

- 단일 `ord` 코드보다 경주 단위 예외가 우선해야 한다.
- 취소·주행중지·실격을 하나의 일반 상태로 합치면 후속 분석에서 의미가 손실된다.

### 다음 실험 아이디어

- 새로운 비표준 코드 또는 예외 경주가 추가될 때 자동으로 검토 목록을 생성한다.

### 결과

- 매출만으로 연승식·복승식 또는 다른 승식을 확정할 수 없다.

## 2026-08-02 — 공식 적중배당 원문 프로파일링

### 실험 내용

- 시장 적격 4,582경주의 7개 승식 `confirmed_odds_raw` 32,074행을 검사했다.
- 원문을 공백 2개로 분리하고 마번 조합, 선택 수와 양수 배당을 검증했다.
- 승식별 원문 길이, 행별 조합 수, 배당 분위수, 중복 마번과 중복 조합을 검사했다.

### 결과

- 빈 원문은 0건이었다.
- 32,074개 행에서 50,494개 공식 적중 조합을 추출했고 파싱 오류는 0건이었다.
- 행별 조합 수는 단승·복승·쌍승·삼복승·삼쌍승 1~2개, 연승 2~4개, 복연승 3~6개였다.
- 마번 16 표기 `(16)`을 포함한 조합은 25개였다.
- 중복 마번, 중복 canonical 조합과 0 이하 배당은 모두 0건이었다.
- 중앙값 배당은 연승식 1.9에서 삼쌍승식 181.9까지 큰 차이가 있었다.

### 해석

- 현재 데이터 형식은 결정론적으로 파싱 가능하지만 한 원본 행에 여러 적중 조합이 존재한다.
- 정규화 Grain은 `경주 × 승식 × 공식 적중 조합`이어야 한다.
- 배당 분포 차이만으로 수익성이나 모델 적합성을 판단할 수 없다.

### 다음 실험 아이디어

- 공식 적중배당 Canonical 테이블을 구현하고 원본 행·조합 수를 대사한다.
- 승식별 극단값 의존도와 적중 조합의 구조를 경주 조건별로 비교한다.

## 2026-08-02 — 동착과 승식별 적중 조합 대사

### 실험 내용

- 복수 적중 조합이 있는 경주를 공식 1~3위와 대조했다.
- 공동 1·2·3위 경주 수와 단승·복승·쌍승·복연승·삼복승·삼쌍승 조합 수를 비교했다.
- 연승식 2개·3개 조합 경주의 등록두수와 최종 유효 출전두수를 비교했다.

### 결과

- 공동 1위 7경주, 공동 2위 14경주, 공동 3위 7경주였다.
- 단승 2조합 7건, 복승 2조합 14건, 쌍승 2조합 21건이 공식 순위와 일치했다.
- 공동 3위 7경주에서 연승 4조합, 복연승 6조합, 삼복승 2조합이 함께 관찰됐다.
- 삼쌍승 2조합 28건은 공동 1·2·3위 7+14+7경주와 일치했다.
- 8두 등록 후 제외마가 발생한 경주에서는 연승 2조합과 3조합이 모두 관찰됐다.

### 해석

- 복수 조합은 데이터 중복이 아니라 동착과 공식 승식 정산 결과다.
- 연승식은 제외 시점에 따른 발매 기준을 현재 경주결과 API만으로 복원할 수 없다.
- 공식 배당 원문을 정산의 최종 근거로 보존해야 한다.

### 다음 실험 아이디어

## 2026-08-02 — 승식 후보 파레토 비교

### 실험 내용

- 유효 출전마 수로 승식별 경주 단위 가능 조합 수를 계산했다.
- 공식 적중 조합 수를 가능 조합 수로 나눠 나이브 적중확률을 계산했다.
- 매출 비중, 나이브 적중확률, 선택 공간과 배당 꼬리비율로 파레토 지배 관계를 비교했다.
- 등록두수 기준과 동착 28경주 제외 결과를 민감도 분석했다.

### 결과

- 비지배 후보는 연승식·복승식·복연승식·삼복승식이었다.
- 단승식은 연승식, 쌍승식은 복승식에 지배됐다.
- 삼쌍승식은 복승식 또는 삼복승식에 지배됐다.
- 유효 출전마와 등록두수가 다른 605경주에서도 집계 기준을 바꾸면 파레토 집합은 동일했다.
- 동착 28경주를 제외해도 파레토 집합은 동일했다.

### 해석

- 연승식은 접근성, 복승식과 삼복승식은 시장 규모, 복연승식은 중간 절충점이라는 서로 다른
  역할이 있어 네 후보를 단일 점수로 서열화할 근거가 없다.
- 확정배당 분포는 시장 구조를 설명하지만 ROI를 의미하지 않는다.

### 다음 실험 아이디어

## 2026-08-02 — 6B 연승 모집단과 Feature 가용성 점검

실험 내용:

- 완료 상태이며 공식 연승 적중 원문이 있는 경주의 출전 결과 상태를 집계했다.
- 공식 연승 적중마와 `race_id + gate_no` 결합 무결성을 검사했다.
- 기본 컬럼 결측과 말·기수·조교사의 경주일 이전 이력 깊이를 측정했다.
- DNS가 없는 경주를 모집단 민감도 집합으로 계산했다.

결과:

- 4,582경주·49,183개 결과 행 중 `is_valid_start` 행은 48,524개였다.
- 공식 연승 양성 13,740행은 모두 출전마와 결합됐고 invalid-start 양성은 0건이었다.
- DNS는 659행·605경주였고, DNS 없는 집합은 3,977경주·42,632 valid-start 행이었다.
- 주행정지 133행과 실격 3행은 실제 출전으로 분류되어 있었다.
- 마체중은 48,524행 전부 결측이었다.
- 과거 출전이 없는 행은 말 4,973개, 기수 334개, 조교사 249개였다.

해석:

- 현재 데이터로 개발용 확률모델 모집단과 타깃은 구성할 수 있다.
- `is_valid_start`는 사후 프록시이므로 실제 발매 마감 모집단을 완전히 복원하지는 못한다.
- DNS 포함 여부에 따른 민감도 비교와 이력 관측창 불완전 플래그가 필요하다.

다음 실험 아이디어:

- 승인된 Feature Snapshot에서 전체 프록시와 DNS 없는 집합의 분포·Calibration 차이를 비교한다.
- 기준모델 이후에만 추가 정보의 증분가치를 시간순 ablation으로 평가한다.

## 2026-08-02 — DNS 605경주 모델링 정책 검증

실험 내용:

- DNS가 있는 완료·공식 연승 경주를 경주 Grain으로 집계했다.
- DNS 수, 유효 출전마, 완주·주행정지·실격, 경주 상태와 7개 공식 승식 완전성을 검사했다.
- 등록·결과 행, 1착과 공식 연승 적중마 수의 무결성을 검사했다.

결과:

- DNS 1두 555경주, 2두 46경주, 3두 4경주였다.
- 601경주(99.34%)가 1~2두 DNS였고 최대 DNS는 3두였다.
- 유효 출전마 중앙값은 10두, 최소는 6두였다.
- 605경주 모두 완료 상태이고 7개 승식, 1착과 2~4개 공식 연승 적중마가 존재했다.
- 경주 취소·결과 미확정·승식 누락·행 수 불일치·미해결 비출전 상태는 0건이었다.
- 주행정지 말이 있는 13경주도 공식 결과와 승식이 정상이며, 실격 동반 경주는 0건이었다.

해석:

- DNS는 정상 시행 경주의 개별 비출전 상태이며 DNS 자체는 경주 단위 제외 근거가 아니다.
- DNS 말만 제외하고 실제 출전마는 보존하는 정책이 데이터 손실과 선택 편향을 줄인다.

다음 실험 아이디어:

- Feature Snapshot 구현 후 DNS 경주와 DNS 없는 경주의 Feature·타깃 분포 차이를 보조 점검한다.
- 최종 선택 후 해당 승식의 타깃과 Point-in-Time Feature 범위를 설계한다.

## 2026-08-08 — API26_2 과거 출전표 Point-in-Time 실제 호출 검증

### 실험 내용

- 서울·부산경남 각 1두의 2024~2025 경주일 4개씩, 총 8개 과거 날짜를 현재 시점에 호출했다.
- 통산·최근1년 출전 및 1·2·3위 횟수를 API4에서 경주일 이전 조건으로 직접 계산해 비교했다.

- 이 분해는 다른 경주 조건을 통제하지 않은 기술적 분해이며 인과효과가 아니다.
