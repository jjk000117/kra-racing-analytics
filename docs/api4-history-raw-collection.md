# API4 2022·2023 Raw 전체 수집 기록

## 결과

2026-08-11에 2022년 전체 수집을 시작했으나 공공데이터포털/KRA API가 모든 요청에 `resultCode=99`, `가용한 세션이 존재하지 않습니다. (100/100)`을 반환하여 수집을 완료하지 못했다. HTTP 200 안에 담긴 API 업무 오류이며 API 키 누락이나 데이터 부재로 판정하지 않는다.

2023년 수집은 같은 외부 장애가 지속되는 상태에서 불필요한 실패 요청을 늘리지 않기 위해 시작하지 않았다. Staging 적재는 수행하지 않았다.

## 실행 결과

| 항목 | 결과 |
|---|---|
| API | API4_3 경주결과 |
| 2022 batch_id | `20260811T133854446046Z_api4_3_d706b8ae` |
| 범위 | 서울(`meet=1`), 부산경남(`meet=3`), 전체 페이지, 페이지 크기 1,000 |
| 요청 | 2건 |
| 성공 / 데이터 없음 / 실패 | 0 / 0 / 2 |
| batch 상태 | `COMPLETED_WITH_ERRORS` |
| 2023 수집 | 시작하지 않음 |

최초 실패 후 20초와 45초 간격으로 2022년 1월 1행 조회를 재확인했으나 같은 세션 포화 응답이 반복되었다.

## Raw audit와 경계 확인

- 실패 응답은 증거 원본으로 보존: 서울·부산경남 Raw JSON 각 1개
- batch audit 무결성 문제: 0건
- 성공 데이터 행: 0건
- `staging.race_result`의 2022년/2023년 행: 각각 0건
- 보호된 모델·평가·진단 산출물 6개 SHA256: 모두 기존 기록과 일치
- API 키: 저장·출력하지 않음

audit 문제 0건은 실패 응답 파일과 Manifest의 계보·해시가 일치한다는 뜻이며 데이터 수집 성공을 뜻하지 않는다. 실패 batch와 Raw 파일은 삭제하거나 덮어쓰지 않는다.

## 재개 절차

1. 소량 1행 요청으로 API 세션 가용성을 확인한다.
2. 정상 응답이면 새로운 batch로 2022년 전체 Raw를 수집하고 audit한다.
3. 같은 방식으로 2023년 전체 Raw를 수집하고 audit한다.
4. 연도·경마장·월별 건수와 Raw/Manifest 무결성을 확인한다.
5. 종료점은 Raw audit이며 Staging 적재는 수행하지 않는다.

외부 서비스 정상화 전에는 collector 정책이나 재시도 로직을 변경하지 않는다.

## 2026-08-11 상태 재확인

2022년 서울 1페이지·1행 최소 요청을 한 번만 실행했으나 다시 HTTP 200 내부의
`resultCode=99`, `가용한 세션이 존재하지 않습니다. (100/100)`이 반환됐다. 추가 재시도와
전체 수집은 수행하지 않았다. 상세한 Raw·Feature 계층 대조는
`docs/api4-raw-feature-gap-audit.md`에 기록한다.
