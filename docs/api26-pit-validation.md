# API26_2 과거 출전표 Point-in-Time 검증

검증일: 2026-08-08  
상태: 소수 표본 실제 호출·API4 Canonical 대조 완료

## 결론

`API26_2`의 과거 경주일 조회 응답에는 서로 다른 시간 성격의 필드가 섞여 있다.

1. **Historical PIT Feature로 사용 가능**: 레이팅, 부담중량, 등록두수, 경주·출전마·관계자 기본정보
2. **값은 유효해 보이나 시점 보장이 부족해 보류**: `ilsu` 등 의미와 산식이 현재 계약과 일치하지 않는 필드
3. **현재값 또는 사후값으로 판단되어 사용 불가**: 통산 및 최근1년 출전·1/2/3위 횟수

통산·최근1년 누적 8개 필드는 동일 말의 2024~2025 네 경주일에서 모두 완전히 동일했다. 2024년
첫 표본은 API4 관측상 이전 출전이 0회였지만 API26은 각각 통산 41회와 82회를 반환했다. 이후
API4의 과거 출전수가 증가해도 API26 값은 변하지 않았다. 따라서 과거 경주일의 당시 누적값이
아니며 Historical Feature에 사용할 수 없다.

반면 현재 경주 사전정보 13개는 8개 표본 모두 API4의 해당 과거 경주 값과 일치했고 레이팅,
부담중량과 등록두수는 날짜별로 실제 변했다. API26이 과거 경주별 출전표 값을 반환한다는 근거로
충분하므로 해당 필드는 Historical PIT 후보로 승인할 수 있다. 단, API26을 지금 수집한 시각이
과거 경기 전 공개시각을 증명하는 것은 아니며 실시간 운영에서는 별도 사전 수집이 필요하다.

- 호출 시각: 2026-08-08
- API4 기준: 현재 DuckDB의 `canonical.race`, `canonical.runner_result`,
  `staging.race_result`
- 배치 ID: `7a7378e8-71ff-4461-959f-953b184c26c6`

## 2. 검증 방법

각 표본 경주일 `D`에 대해 API4에서 다음 값을 독립 계산했다.

```text
통산 사전 출전수 = count(is_valid_start = true and race_date < D)
통산 사전 1/2/3위 = count(is_valid_finish = true and rank = 1/2/3 and race_date < D)
최근1년 출전·1/2/3위 = D - 1 year <= race_date < D
당일 포함 누적 = race_date <= D
```

API26 통산·최근1년 값이 사전 누적, 당일 포함 누적 또는 이후 결과가 섞인 값인지 비교했다. 동일
말의 네 날짜에서 API26 값의 distinct 수와 API4 사전 누적의 증가량도 확인했다.

현재 경주 기본정보는 API26과 API4의 해당 경주 행을 직접 비교했다. 경마장 명칭은 코드로
정규화했고 숫자는 수치형으로 비교했다.

### 통산 및 최근1년 1·2·3위

- `0046117`: API26 통산 `1/5/3`, 최근1년 `1/0/0`으로 네 날짜 모두 고정
- `0042912`: API26 통산 `1/5/10`, 최근1년 `0/0/2`로 네 날짜 모두 고정
- 두 말의 API4 사전 1·2·3위 횟수는 날짜가 진행되면서 실제로 증가했지만 API26은 변하지 않음
- 8개 누적 필드 모두 말별 4개 날짜의 distinct 값이 각각 1개

따라서 다음 필드는 모두 판정 3이다.

| API26 필드 | 의미 | 판정 |
|---|---|---|
| `rcCntT` | 통산 출전수 | 3 — 사용 불가 |
| `ord1CntT`, `ord2CntT`, `ord3CntT` | 통산 1·2·3위 횟수 | 3 — 사용 불가 |
| `rcCntY` | 최근1년 출전수 | 3 — 사용 불가 |
| `ord1CntY`, `ord2CntY`, `ord3CntY` | 최근1년 1·2·3위 횟수 | 3 — 사용 불가 |

API26 누적값은 값 자체가 틀렸다고 단정하는 것이 아니라 **조회한 과거 경주일 당시의 값이
아니라는 판정**이다. 현재 시점 또는 현재에 가까운 누적 프로필이 과거 출전표 행에 결합된 것으로
해석된다.

## 5. 보류 필드

`ilsu`는 API26 응답에서 날짜별로 달라졌지만 API4로 계산한 `days_since_last_start`와 일치하지
않았다. 필드 의미와 산식을 공식적으로 확정하기 전까지 대체 Feature로 사용하지 않는다.

상금 관련 `chaksunT`, `chaksunY`, `chaksun_6m`은 이번 검증의 직접 비교 범위가 아니다. 누적
성적 필드와 같은 시간 위험이 있고 기존 정책에서도 사용 금지이므로 판정 3을 유지한다.

## 6. 영향과 권고

- API26 누적 성적 8개는 Historical Feature, 라벨, 보정값으로 사용하지 않는다.
- 말·기수·조교사의 누적 이력은 계속 API4에서 `race_date < feature_as_of`로 직접 계산한다.
- API26의 레이팅·부담중량·등록두수와 기본 출전정보는 과거 경주별 PIT 후보로 사용할 수 있다.
- API4에도 같은 값이 있으므로 첫 Snapshot을 위해 API26 과거 범위를 대량 수집할 필요는 없다.
- 미래 운영에서는 API26을 경기 전에 수집해 실제 `available_at` 증거를 별도로 축적한다.
- 표본은 2두·8경주이므로 스키마 전체 품질을 보증하지는 않지만, 누적 필드의 시간 누수 판정은
  날짜별 불변성과 최초 경주의 미래값 반영이 동시에 확인되어 신뢰도가 높다.
